Split, merge, bundle, unbundle

PROTOTYPE — throwaway logic for testing a declarative filesystem projection. It is not production Taku code.

Question: Can one small Resource Type configuration reversibly split a Kibana Skill JSON object into an Agent Skill directory and merge it back, while passing all unclaimed frontmatter values through automatically and remaining independent from collection bundling such as NDJSON?
files ⇄ merge / split ⇄ Resource Objects ⇄ bundle / unbundle ⇄ operation payload
Actual ESDiag corpus check: 24 files (one SKILL.md and 23 references) merged and split successfully. Every frontmatter value matched the Kibana JSON payload, the Resource Object round trip was exact, and every reference file remained byte-for-byte identical. SKILL.md remained semantically equal but its YAML frontmatter formatting was normalized.

Production direction: use pulldown-cmark with YAML metadata blocks enabled to locate the frontmatter and Markdown body, then decode the metadata text as one generic YAML mapping. The projection does not know individual frontmatter field names.
