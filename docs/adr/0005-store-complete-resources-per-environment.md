# Store complete Resources per Environment

Each Environment will have an independent, potentially partial Resource Inventory containing complete Canonical Representations, with no shared base inheritance or field-level overlays in the MVP. A Single layout stores `target/type/item` at the Project root and records its one Environment name in `.taku/project.yml`; a Multi layout stores `environment/target/type/item`. Each explicitly named Target references an installed Application and allows an Environment to contain multiple instances of that Application, such as `dev/es1/mappings/...` and `dev/es2/mappings/...`; Target names are scoped to their Environment. Promotion copies Universal-ID snapshots only between compatible mapped Targets, either across Multi-layout Environments or two explicitly named Single-layout Project roots, while Target-scoped IDs are not promotable; this accepts duplication and portability constraints for transparent file operations and Git diffs.
